## الرفع على GitHub Pages

1. يحتوي المستودع العام `el7usseinelabd-ux/ads.landing-law` على ملفات الصفحة في الجذر؛ لا حاجة إلى بناء عبر npm.

## ربط الصفحة بالمجموعة الإعلانية

تبدّل الصفحة العنوان والوصف وقسم الخدمة ورسالة واتساب والنافذة المنبثقة بحسب المجموعة الإعلانية. للأدق، أضف معامل `service` إلى رابط الإعلان نفسه لكل مجموعة، بدل الاعتماد على تخمين الخدمة من الكلمة المفتاحية:

| المجموعة / أمثلة الكلمات | المعامل في الرابط النهائي |
|---|---|
| محامي في جدة، مكتب محاماة جدة، رقم محامي جدة | `?service=general` |
| محامي تجاري جدة، قضايا تجارية | `?service=commercial` |
| محامي شركات، تأسيس شركات، حوكمة | `?service=companies` |
| منازعات شركاء، تصفية شراكة | `?service=partnership` |
| محامي عمالي، حقوق عمالية | `?service=labor` |
| محامي عقاري، نزاع إيجار | `?service=realestate` |
| أحوال شخصية، طلاق، نفقة، حضانة، ميراث | `?service=family` |
| صياغة عقود، مراجعة عقد | `?service=contracts` |
| محامي جنائي / جزائي | `?service=criminal` |
| محامي تنفيذ، تحصيل حقوق | `?service=execution` |
| استشارة قانونية | `?service=consultation` |

مثال رابط نهائي: `https://el7usseinelabd-ux.github.io/ads.landing-law/?service=labor`

أمثلة: أضف `?service=labor` إلى Final URL لمجموعة الإعلانات العمالية، و`?service=family` لمجموعة الأحوال الشخصية. مرّر معاملات القياس التالية في Final URL suffix في Google Ads، دون علامة `?` في أولها:

```
utm_source=google&utm_medium=cpc&utm_campaign={campaignid}&utm_content={adgroupid}&utm_term={keyword}
```

يقرأ الموقع كلمات البحث من `keyword` أو `utm_term` أو `search_term` أو `term`، ويصنفها احتياطيًا عند غياب `service` صالح. يزيل التطبيع بعض اختلافات كتابة العربية، وتُفحص الخدمات الأكثر تخصيصًا قبل الفئات العامة. `service` الصريح هو الأدق والأعلى أولوية، ويغيّر الصفحة ورسالة واتساب بحسب الخدمة. لا يُعرض نص الكلمة الواردة مباشرة ولا يُدرج كـHTML. تبقى معاملات الحملة موجودة عند اختيار مجال آخر داخل الصفحة.

**ربط فعلي للحملات:** لم يتم تعديل Google Ads أو إنشاء حملات من هذا المستودع؛ اضبط `service` في Final URL لكل مجموعة إعلانية داخل حساب Google Ads، ثم اختبر رابطًا لكل فئة قبل الإطلاق.

مرجع Google حول معاملات ValueTrack: https://support.google.com/google-ads/answer/6305348

## قياس الاتصال وواتساب

كل نقرة اتصال أو واتساب تنشئ حدثًا داخل `dataLayer` باسم:

```
contact_click
```

حقول الحدث:

| الحقل | المعنى |
|---|---|
| `contact_channel` | `whatsapp` أو `phone` |
| `contact_placement` | موضع الزر، مثل `header`, `hero`, `service`, `contact`, `request`, `mobile-bar`, `desktop-float`, `welcome-popup` |
| `legal_service` | الخدمة التي اختارها الزائر للتواصل |
| `landing_service` | الخدمة التي تعرضها الصفحة حاليًا |

**هذه أحداث جاهزة للربط وليست تتبعًا مفعّلًا في Google Ads.** لا توجد معرفات حساب أو حاوية أو تحويلات مضافة، لعدم تزويدنا بها. لا تُرسل بيانات إلى Google في النسخة الحالية، ولا يرسل الحدث رقم العميل أو محتوى محادثته.

للربط الفعلي: أضف كود حاوية Google Tag Manager الخاصة بالمكتب في الموضع المخصص داخل `head` وكودها التكميلي بعد بداية `body`؛ أنشئ مشغل Custom Event للاسم `contact_click`، مع شرط `contact_channel=whatsapp` لتحويل واتساب، وآخر للاتصال إذا لزم. اربط كل مشغل بوسم Google Ads Conversion Tracking باستخدام Conversion ID وConversion Label من حساب المكتب، وأضف Conversion Linker حسب إعداد الحاوية. اختبر باستخدام Tag Assistant قبل إطلاق الإعلان، وحدّث سياسة الخصوصية وإعدادات الموافقة بما يطابق أدوات القياس التي ستفعلها.

مرجع Google للـdataLayer: https://developers.google.com/tag-platform/tag-manager/datalayer

**نقرة واتساب لا تعني إرسال رسالة، ونقرة الهاتف لا تثبت إجراء مكالمة.** سمّ التحويل «نقرة واتساب» عند قياسها. قياس التواصل المؤهل أو العميل المتعاقد يحتاج بيانات فعلية من المكتب وربطًا إضافيًا بالحملة، وليس حدث نقرة الصفحة وحده.

## تحديث نافذة التواصل والتأثيرات

تظهر نافذة التواصل بعد مهلة قصيرة مرة واحدة في جلسة التصفح، وتخصص العنوان والنص حسب الخدمة الإعلانية. لمراجعتها مرارًا أضف `&popup=1` إلى رابط المعاينة؛ يبقى السلوك المعتاد مرة واحدة للجلسة. كما تعيد المحاولة إذا عاد المستخدم إلى تبويب كان في الخلفية. لا اتصال ولا رسالة تلقائية.

تعكس الواجهة الجديدة النموذج المرجعي بتباين فحمي/نحاسي، وبطل مركزي، وصورة كبيرة وقسم تعريف وخدمات أوضح، وبطاقات نظيفة، وروابط كلمات بحث ممتدة، وزري اتصال وواتساب ثابتين على الكمبيوتر. الحركات هادئة وتحترم إعداد تقليل الحركة.

يميز التتبع موضع الأزرار الجديدة بالقيمتين `welcome-popup` و`desktop-float`. ويجهز حدث `welcome_popup_view` عند ظهور النافذة، دون تسجيله كتحويل مكتمل. يبقى الربط بـGoogle Ads غير مفعّل حتى إضافة إعدادات الحساب.

اختُبر تخصيص صفحة العملة عبر `service=labor`، وظهور النافذة في وضع `popup=1`، وعناوين وأزرار الاتصال وواتساب، وروابط عبارات البحث. لم يُفعّل نشر GitHub Pages.
